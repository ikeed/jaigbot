**Title:** Update module ownership and refactor legacy components

**Purpose:** This PR implements a modularization architecture for the training platform, moving AIMS from a monolithic app into a module-based design with generic core infrastructure and proof-of-concept support for a second module (interview practice).

---

## Core Changes

### 1. **Module-Based Architecture** 
The PR introduces a clean module contract and registry system:

- **New `app/core/` package** defines module interfaces and lifecycle:
  - `TrainingModule` protocol with methods like `handle_turn()`, `build_summary()`, `build_archive_envelope()`
  - `ModuleRegistry` to register and resolve modules at startup
  - Generic response/session envelope types for cross-module compatibility
  
- **AIMS moved to `app/modules/aims/`** with full service relocation:
  - All AIMS services now live under `app/modules/aims/services/`
  - AIMS docs, prompts, and models move to module namespace
  - Module exposes a manifest with dialogue roles, features, and branding
  
- **Interview Practice module** added as proof-of-concept at `app/modules/interview/`

### 2. **Dependency Injection & Runtime Resolution**
- `app/config.py` adds `ACTIVE_MODULE` setting (defaults to `"aims"`)
- `app/main.py` bootstraps the module registry and active module on startup
- Routes now receive `get_active_module()` dependency for module dispatch

### 3. **Unified Chat Orchestration**
- `ChatOrchestrator` now delegates to the active module's `handle_turn()` method
- Removed hardcoded coaching vs. legacy branching
- Module response formatting is module-owned via `format_module_response()`

### 4. **Session & Thread Management**
- `ChatContextBuilder` now accepts module dialogue roles (counted roles, counterpart roles, display names)
- `chainlit_thread_state.py` tracks `module_id` per thread to prevent resume across modules
- Startup artifact support for flexible UI rendering (e.g., interview briefing cards)

### 5. **Archive & Storage Refactoring**
- Generic `ModuleArchiveEnvelope` replaces AIMS-specific schema
- Each module implements `build_archive_envelope()` to shape its own archive
- `StorageService` delegates archive serialization to the active module

### 6. **Branding & UI Customization**
- `BrandingSpec` in module manifest controls app title, loading text, avatars
- Templates accept dynamic `shell_title` and `module_title` from active module
- Avatar SVGs retitled from "AIMSBot" to "Training platform"
